# Work IQ - Idea to Code

**Audience:** Developers, technical leads, and solution architects evaluating end-to-end Copilot workflow value

## Overview

This optional module introduces the full idea-to-code cycle as a fast, repeatable workflow. You will follow a guided demo that moves from a raw business request through requirement refinement, prototype direction, stakeholder storytelling, and implementation handoff. The goal is to show how Copilot-assisted workflows can accelerate planning and delivery readiness before deep implementation begins.

### Key Concepts

1. Idea-to-code conceptual flow and the artifacts produced at each stage.
2. Microsoft Work IQ positioning and where it fits with GitHub Copilot workflows.
3. Requirement collection and refinement using iterative prompts and clarification loops.
4. Rapid prototype generation from scoped prompts with explicit assumptions.
5. Demo storytelling and value framing for technical and business audiences.
6. Handoff standards from concept artifacts into issues, projects, and pull requests.

## Prerequisites

- Access to this repository and GitHub Copilot-enabled environment.
- Basic familiarity with [GitHub Copilot](https://docs.github.com/en/copilot), [Issues](https://docs.github.com/en/issues), and [Pull requests](https://docs.github.com/en/pull-requests).
- (Recommended) Review [Planning and tracking with projects](https://docs.github.com/en/issues/planning-and-tracking-with-projects) before the handoff exercise.

## Exercises

### Exercise 1: Idea-to-code conceptual overview

**Objective:** Identify the full lifecycle stages from idea intake to engineering-ready handoff.

**Exercise type:** Instructor-Guided

1. Review the lifecycle stages shown in the demo: idea intake, requirement refinement, prototype direction, review framing, and delivery handoff.
2. For each stage, capture one expected artifact (for example: clarified user story, scoped tasks, or handoff checklist).
3. Map each artifact to the team role that owns it (product, developer, reviewer, or tech lead).

**Expected Outcome:** You can describe the lifecycle in order and name the output expected from each stage.

**Knowledge Check:**
1. Which stage prevents ambiguous scope from reaching implementation?
2. What artifact is most important before coding starts, and why?

### Exercise 2: Microsoft IQ overview

**Objective:** Explain where Work IQ fits in a Copilot-enabled development workflow.

**Exercise type:** Whiteboard/Discussion

1. Review how Work IQ complements Copilot capabilities across planning and implementation, using [Using GitHub Copilot](https://docs.github.com/en/copilot/using-github-copilot).
2. Compare Work IQ-assisted planning outputs with traditional manual intake.
3. Identify one scenario where Work IQ provides clear value (for example: reducing unclear requirements before issue creation).

**Expected Outcome:** You can explain Work IQ value in terms of speed, clarity, and handoff quality.

**Knowledge Check:**
1. What problem does Work IQ solve before coding begins?
2. How does this module connect to deeper coding-focused Copilot modules?

### Exercise 3: Requirement collection and refinement with Work IQ

**Objective:** Turn a raw user story into a refined, implementation-ready requirement set.

**Exercise type:** Instructor-led

1. Start from a sample story (for example: "As a student, I want to view enrollment history with grades").
2. Use iterative prompts to refine acceptance criteria, edge cases, constraints, and validation expectations.
3. Convert the refined requirement into clear implementation tasks and review boundaries.
4. Confirm each task has a success signal and ownership.

**Expected Outcome:** You produce a requirement summary that is specific enough to become issue-ready content.

**Knowledge Check:**
1. What refinement step removed the most ambiguity?
2. Which requirement detail is most likely to affect testing scope?

### Exercise 4: Rapid prototype generation from prompts

**Objective:** Generate a prototype direction from prompts without skipping validation thinking.

**Exercise type:** Instructor-Guided

1. Prompt for a prototype approach that includes data model impact, API/UI touchpoints, and test implications.
2. Review generated output for assumptions, missing constraints, and technical risk.
3. Revise the prompt to improve specificity and produce a cleaner second draft.
4. Capture what changed between first and second draft quality.

**Expected Outcome:** You can guide prompt iterations to improve prototype usefulness and implementation readiness.

**Knowledge Check:**
1. Which prompt detail most improved prototype quality?
2. What assumptions must be validated before implementation starts?

### Exercise 5: Demo storytelling and value framing

**Objective:** Communicate the demo in a way that resonates with both engineers and decision-makers.

**Exercise type:** Whiteboard/Discussion

1. Build a short narrative: problem, workflow, output, and measurable value.
2. Frame value in delivery terms (faster requirement clarity, fewer review loops, clearer handoff).
3. Tailor your message for two audiences: engineering team and technical leadership.

**Expected Outcome:** You can present the same demo with role-appropriate value messaging.

**Knowledge Check:**
1. What proof point best demonstrates value for engineering teams?
2. What proof point best demonstrates value for technical leaders?

### Exercise 6: Handoff from concept to implementation

**Objective:** Convert idea-to-code outputs into execution artifacts in GitHub.

**Exercise type:** Instructor-led

1. Translate refined outputs into issue content with scope, acceptance criteria, and dependencies using [Issues](https://docs.github.com/en/issues).
2. Add tracking fields and status placement in a project board using [Planning and tracking with projects](https://docs.github.com/en/issues/planning-and-tracking-with-projects).
3. Define pull request boundaries and review checkpoints using [Pull requests](https://docs.github.com/en/pull-requests).
4. Confirm the handoff package is ready for implementation without additional discovery.

**Expected Outcome:** You produce a concept-to-implementation handoff package that supports immediate engineering execution.

**Knowledge Check:**
1. Which handoff artifact most reduces rework during implementation?
2. What should trigger another refinement loop before coding?

## Completion Criteria

1. You can explain the idea-to-code lifecycle and the output expected at each stage.
2. You can position Work IQ in relation to GitHub Copilot workflows and planning outcomes.
3. You can refine requirements into clear, actionable implementation tasks.
4. You can use prompt iteration to improve prototype direction quality.
5. You can frame demo value for both technical contributors and leadership audiences.
6. You can hand off concept outputs into issues, projects, and pull request scope with minimal ambiguity.
